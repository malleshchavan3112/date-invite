# Database Schema

## 1. Tables

### `invitations`
Stores created date invitations generated by the creator.

```sql
CREATE TABLE invitations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    slug TEXT UNIQUE NOT NULL,
    creator_name TEXT NOT NULL,
    creator_email TEXT NOT NULL,
    title TEXT DEFAULT 'Would you go on a date with me?',
    intro_text TEXT DEFAULT 'Someone thinks you are wonderful and wants to invite you somewhere special.',
    active BOOLEAN DEFAULT TRUE NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL
);
```

### `responses`
Stores recipient responses (both YES date questionnaire completions and confirmed NO completions).

```sql
CREATE TABLE responses (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    invitation_id UUID NOT NULL REFERENCES invitations(id) ON DELETE CASCADE,
    answer TEXT NOT NULL CHECK (answer IN ('yes', 'no')),
    recipient_name TEXT,
    date_type TEXT,
    preferred_day TEXT,
    preferred_time TEXT,
    date_vibe TEXT,
    message TEXT,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL,
    submitted_at TIMESTAMPTZ DEFAULT now() NOT NULL
);
```

### `response_events` (Optional / Analytics)
Tracks lifecycle milestones (e.g. link opened, button clicked) to populate C03 status without logging personal information.

```sql
CREATE TABLE response_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    invitation_id UUID NOT NULL REFERENCES invitations(id) ON DELETE CASCADE,
    event_type TEXT NOT NULL, -- e.g. 'link_opened', 'yes_clicked', 'no_clicked'
    metadata JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ DEFAULT now() NOT NULL
);
```

## 2. Indexes

```sql
-- Fast lookup by invitation slug (recipient routing)
CREATE UNIQUE INDEX idx_invitations_slug ON invitations(slug);

-- Lookup invitations by creator email (for future dashboard or status)
CREATE INDEX idx_invitations_creator_email ON invitations(creator_email);

-- Fast join from invitation to responses
CREATE INDEX idx_responses_invitation_id ON responses(invitation_id);

-- Enforce maximum of one response per invitation
CREATE UNIQUE INDEX idx_single_response_per_invitation ON responses(invitation_id);

-- Fast join for event logging
CREATE INDEX idx_response_events_invitation_id ON response_events(invitation_id);
```

## 3. Row Level Security (RLS) & Privacy Policies

Enable RLS on all tables:

```sql
ALTER TABLE invitations ENABLE ROW LEVEL SECURITY;
ALTER TABLE responses ENABLE ROW LEVEL SECURITY;
ALTER TABLE response_events ENABLE ROW LEVEL SECURITY;
```

### `invitations` Policies
1. **Public Read (Excluding Sensitive Email)**:
   - Recipient clients can query active invitations by slug.
   - Recommended implementation: Use a PostgreSQL View `public_invitations` or Server Action that explicitly excludes `creator_email`.
   ```sql
   CREATE VIEW public_invitations AS
   SELECT id, slug, creator_name, title, intro_text, active, created_at
   FROM invitations;
   ```
2. **Public Create (Creator Flow C01)**:
   - Unauthenticated creators can insert a new row through Server Action or public insert policy:
   ```sql
   CREATE POLICY "Allow public invitation creation"
   ON invitations FOR INSERT
   WITH CHECK (true);
   ```

### `responses` Policies
1. **Public Insert**:
   - Recipients can insert their response as long as the parent invitation is active:
   ```sql
   CREATE POLICY "Allow recipient response submission"
   ON responses FOR INSERT
   WITH CHECK (
       EXISTS (
           SELECT 1 FROM invitations 
           WHERE invitations.id = responses.invitation_id 
           AND invitations.active = true
       )
   );
   ```
2. **Restricted Read**:
   - Responses are NOT publicly readable.
   - Reading responses is restricted to Server Actions using Supabase service-role client (or authorized creator session).

## 4. Privacy & Data Integrity Rules
- `creator_email` is strictly private and never exposed to recipient client requests.
- `answer` column only permits `'yes'` or `'no'`.
- Duplicate submissions for the same `invitation_id` are prevented by the unique index `idx_single_response_per_invitation`.
- All timestamps use UTC `timestamptz`.
